# Development workflow

1. Create a small issue or task.
2. Implement one coherent change.
3. Run relevant tests.
4. Review and understand the diff.
5. Commit with a meaningful message.

Examples:

- `feat: parse common syllabus date formats`
- `test: cover same-day workload conflicts`
- `feat: add deadline review controls`
- `docs: explain PDF limitations and AI usage`

Do not create fake progress or empty commits. Commit history should reflect the real learning and development process.
